# Spec: NL2SQL 动态指标计算与先进 RAG 升级

## 1. 背景
当前系统能够完成标准 NL2SQL 查询，但对“非预定义指标”的自然语言计算需求支持不足。用户希望通过对话直接描述取数来源、计算逻辑和分析约束，并获得可复现结果。与此同时，系统运行在单机环境，需要严格控制资源竞争与安全风险。

## 2. 范围

### In Scope
- 新增“动态指标计算”能力（SQL 取数 + 受限代码执行）。
- 升级 RAG 为可评分、可重写、可降级的流程（Self-RAG/CRAG 风格）。
- 引入 GraphRAG（基于语义视图 Join 图的多跳关系增强检索）。
- 建立单机资源治理、安全审计与回滚机制。

### Out of Scope
- 全量 BI 可视化平台改造。
- 多机分布式调度改造。
- 非业务数据源接入扩展。

## 3. 术语
- 动态指标：不在语义层预定义、由用户临时描述的计算目标。
- SQL Specialist：负责可约束 SQL 生成与执行。
- Code Analyst：负责动态逻辑计算的代码生成、执行与修复。
- RAG Grader：负责评估召回证据质量并触发重检索或降级。

## 4. 功能需求

### FR-1 动态指标计算编排
- 系统应支持将用户请求拆分为“取数子任务”和“计算子任务”。
- 当语义层无对应指标定义时，系统应自动进入动态计算路径。

### FR-2 受限代码执行
- 系统应支持在受限执行环境中运行计算代码。
- 系统应返回结构化结果：最终值、中间统计、执行摘要。

### FR-3 检索质量控制
- 系统应对 RAG 召回结果进行相关性评分。
- 当评分低于阈值时，应触发查询重写与重检索。
- 当重检索失败时，应触发降级策略并给出可解释说明。

### FR-4 图关系增强
- 系统应从 `ai_views.yaml` 构建关系图。
- 在多表语义查询中，应利用图关系补全候选表和字段。

### FR-5 双环路修复
- SQL 执行失败时，应进入 SQL 修复环路。
- 代码执行失败时，应进入代码修复环路。
- 达到最大重试次数后，系统应返回可读错误与建议下一步。

## 5. 非功能需求

### NFR-1 单机资源治理
- 检索、索引构建、查询执行、代码执行应受并发上限约束。
- P95 延迟目标和资源上限须被监控与告警。

### NFR-2 安全
- SQL 必须只读。
- 代码执行必须限制导入模块、CPU/内存/超时、网络与文件权限。
- 全链路审计记录必须可追踪。

### NFR-3 可观测性
- 记录每次请求的检索证据、SQL、代码、重试轨迹和最终结果。
- 支持按会话与用户维度回放。

## 6. 接口与数据契约
- 请求输入：自然语言问题 + 可选 thread_id。
- 中间结构：
  - RetrievalEvidence：证据片段、来源、分数。
  - DynamicCalcPlan：取数意图、计算步骤、容错策略。
  - DynamicCalcResult：结果值、中间统计、执行日志摘要。
- 响应输出：文本为主，可附结构化块供前端渲染。

## 7. 验收标准
- 动态指标测试集 Success@1 达到目标阈值。
- SQL 执行成功率与结果一致性达到目标阈值。
- 安全违规率为零（越权 SQL、写操作、越界代码执行）。
- 单机稳定性满足并发压测门槛。

## 8. 风险与缓解
- 风险：动态代码带来安全与性能不确定性。
- 缓解：强隔离、配额、超时、白名单、审计与降级。
- 风险：GraphRAG 增加时延。
- 缓解：图缓存、候选裁剪、分层检索与早停。

## 9. Benchmark 与实验协议

### 9.1 公共基准
- Spider 2.0、BIRD：复杂 SQL 与跨库泛化主基准。
- DuSQL / CSpider：中文查询能力基准。
- Dr.Spider：鲁棒性与抗噪能力基准。
- SParC / CoSQL（可选）：多轮会话能力基准。

### 9.2 企业基准
- 建立“动态指标”专用评测集，覆盖取数、计算逻辑、数据类型约束与异常场景。
- 样本需包含可复算真值与口径说明，支持端到端结果核对。
- 详细规则以 `enterprise_benchmark_data_design.md` 为准。

### 9.3 对照实验要求
- 必须进行 Embedding、模型、检索链路、修复策略四类对照。
- 所有对照组使用同一测试集与同一资源配额。
- 输出统计显著性结论，不仅报告单次最好成绩。

### 9.4 评测指标
- 准确性：Execution Accuracy、Test-Suite Accuracy、Dynamic Metric Success@1。
- 稳定性：P95 延迟、超时率、失败重试率。
- 安全性：越权率、危险 SQL 拦截率、沙箱违规率。
- 可解释性：证据链完整率、人工复核通过率。

## 10. 微调与后训练策略

### 10.1 决策原则
- 先工程优化，后训练。
- 仅在达到触发门槛时进入微调与后训练。

### 10.2 触发门槛
- 核心指标连续两轮提升 <2pp 且仍未达上线阈值。
- 错误归因中模型能力缺口 >40%。
- 复杂动态指标样本长期低于目标成功率。

### 10.3 数据设计
- 数据配比：70% 脱敏真实日志、20% 合成难例、10% 对抗样本。
- 标注结构：
  - 文本输入、schema 快照、候选证据、期望计划、gold SQL/代码、真值结果。
  - 错误标签（检索错/规划错/执行错/验证错）。
- 切分策略：时间切分 + schema 切分，避免训练测试泄漏。

### 10.4 训练路径
- 阶段 1：SFT 对齐格式、工具调用、拒答与安全行为。
- 阶段 2：偏好优化（DPO/排序）降低误调用与无效步骤。
- 阶段 3：验证器约束（可执行性、引用一致性、安全规则）做过滤或奖励。
